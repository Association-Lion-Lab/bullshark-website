// 01 — Sovereignty first

There are no “Bullshark servers”.

On a hosted platform, your conversations travel through servers you don't control, in a country you don't live in, owned by a company you can't audit. Terms change, servers get shut down overnight, data gets mined.

With Bullshark, there is no company between you and your data. Your server runs on your hardware, in your country, under your rules. Wherever you host it, that's where your data lives. Full stop.

A VPS in your city

Pick the provider and the jurisdiction. HTTPS guides with Caddy + OVH or Hetzner DNS — no Cloudflare dependency.

A box in your living room

A single native Linux binary or a Docker container. Updates keep your data: migrations run on start.

A Raspberry Pi under your desk

ARM64 builds are published alongside x64. Small footprint, your rules.

Built in, with adaptive quality per viewer.

Configurable input modes and hotkeys. OS-level global mute via the desktop app.

Noise suppression

RNNoise + noise gate, processed client-side. Your audio never leaves your machine for that.

Soundboard

Play sounds straight into voice channels.

In-game overlay

See who is talking without alt-tabbing out of your game (desktop app).

Roles & permissions

Granular control, per channel and per role.

Moderation

Timeouts, slow mode, voice server-mute. Owner-only backup export/import.

Plugins

Extend your server with a typed SDK: events, slash-commands, messages, voice, UI slots.

Mobile

Installable PWA with push notifications.

Zero telemetry

No analytics, no tracking, no phoning home.

// 04 — Deploy

Up in three commands.

Grab the native Linux binary (x64 or ARM64) or build the Docker image. Then open http://localhost:4991.

  • Open 4991/tcp (web app + API) and 40000 tcp+udp (WebRTC media).
  • Put it behind HTTPS before exposing it — follow the Caddy guide.
  • Coming from Sharkord? A migration guide is available.
Owner token

On first launch, Bullshark prints an owner token in the console. It is your master key: store it securely. Lost it? ./bullshark --new-owner-token issues a new one and revokes the old.

Full getting-started guide 
# x64 — use bullshark-linux-arm64 on ARM (Raspberry Pi…)
$ curl -L https://github.com/Neckript/bullshark/releases/latest/download/bullshark-linux-x64 -o bullshark
$ chmod +x bullshark
$ ./bullshark
# No pre-built image yet: build it from source.
# The image packages the server binary (apps/server/build/out),
# see docs/getting-started.md for the build step.
$ git clone https://codeberg.org/The_Neckript/bullshark.git
$ cd bullshark
$ docker build -t bullshark:local .
$ docker run -d \
    -p 4991:4991/tcp \
    -p 40000:40000/tcp \
    -p 40000:40000/udp \
    -v ./data:/home/bun/.config/bullshark \
    --name bullshark \
    bullshark:local

// 05 — Bullshark Desktop

A native client. No bundled server, no hardcoded URL.

Point the app at your own instance and it opens your server full-screen, in its own isolated browser session. Windows, macOS and Linux.

Download Source code

v1 builds are not code-signed yet: macOS Gatekeeper and Windows SmartScreen will warn on first launch. Auto-update works on Windows and Linux.

  • Multi-server

    Each server keeps its own session (separate cookies & storage). Stay signed into several instances at once.

  • Lives in the tray

    Switch servers, toggle your mic or notifications without opening the window.

  • Global mute hotkey

    OS-level and configurable — works while your game has focus.

  • Native notifications

    With a do-not-disturb switch one click away.

// 06 — Plugin SDK

Mod your server. Declare what you touch.

A plugin is a folder with a manifest.json and a server and/or client entry point. The server builds the plugin context from the capabilities it declares — nothing more.

  • events
  • commands
  • actions
  • messages
  • settings
  • data
  • voice
  • ui
  • hooks.onBeforeFileSave
  • client.slots
Not a sandbox

Capabilities restrict the SDK surface, not system privileges. Only install plugins you trust — and run the server in Docker.

Plugin SDK
plugins/welcome/manifest.json
{
  "id": "welcome",
  "name": "Welcome",
  "author": "you",
  "description": "Logs who joins",
  "version": "1.0.0",
  "sdkVersion": 1,
  "capabilities": ["events"]
}
plugins/welcome/server/index.js
const onLoad = (ctx) => {
  ctx.events.on('user:joined', ({ username }) => {
    ctx.log(`${username} joined the server`);
  });
};

export { onLoad };

// 07 — Roadmap

Beta today. Stable is the target.

The core is complete: text, voice, screen sharing, moderation, plugins, PWA and desktop app. Expect rough edges — report them.

Shipped

  • Voice stability fixes (voice freeze after 10s)
  • Push-to-Talk + VAD, client-side noise suppression
  • Soundboard, voice grid, in-game overlay
  • Granular roles, threads, mobile PWA
  • Server backup export/import from the UI
  • HTTPS guides: Caddy + OVH / Hetzner DNS
  • v0.1.0 — beta

Next

  • Clean voice under heavy CPU load (while gaming)
  • GPU-encoded screen sharing on Windows
  • Audio redundancy (RED) for lossy Wi-Fi / 4G
  • Import a Discord server from a template link
  • Deployment guides: OVH, Hetzner, Raspberry Pi, bare metal

Target

v1.0.0

Stable release. Later: next-gen Opus packet-loss recovery (DRED) once browsers ship it.
